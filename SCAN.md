# Verification scope

This repository contains source text, fictional tests, public documentation and empty configuration placeholders. It has no runtime snapshot, credentials, vendor archive or original private Git history. The public repository has its own history; a checkout may have an `origin` remote.

`npm test` runs the exported suites in an isolated temporary HOME and temporary-data root, with inherited account/model credentials removed. HTTP, models, map results, notifications and media requests are mocked. Coverage includes classified record persistence/corruption, feature refusals and visibility, exact host account binding, duplicate messages, stable chunk identities and uncertain-operation recovery. Private-host integration assertions were excluded with the private host; their original behavior is not certified here.

`npm run check` checks every shipped JavaScript file's syntax before running tests. `tests/public-pair-console.test.js` adds host-level checks for speaker selection, A-added/B-visible places and visited history, daily-question sealing through a cold reopen, challenge callback results for both roles, savings accumulation and contributor-only undo, personal owner-only permissions, the real console entrypoint and its speaker prompts, and the demo's five scenes and cleanup on both success and failure. Pair store schemas and visibility rules are reused rather than duplicated.

`npm run demo` runs five scenes through the actual local pair console: a shared place is added and marked visited; two daily answers unlock a reveal; two challenge answers produce a consistency result through per-role notices; two savings entries accumulate to 80 of 200 yuan (40%); and an explicitly simulated weather briefing exercises role-local city selection and delivery controls. Every scene prints both fictional viewpoints. Its temporary runtime is removed in `finally`; the clock and challenge selection are deterministic, with no model or network requests.

The public experience simulates two roles in one local terminal. Role selection is not authentication, and terminal input/scrollback is visible to the operator. Local callback notices are in-memory only; daily reveals and feature records follow their stores' persistence rules. Real two-account WeChat connectivity and relay are not included. The optional network host still accepts only its configured owner and cannot switch roles through message text. These checks do not establish live provider availability, account authorization, actual recipient delivery, model quality, background-service installation or deployment.

Quota-fallback validation (2026-11-12): `npm run check` passes syntax validation and all **1078 tests**, with zero failures or skips, including **28** fallback core/host tests. The suite also exercises the five-scene offline demo. This records local verification only, not publication, live quota recovery or real-account acceptance.

Ordinary-chat performance validation adds 52 fictional lane cases, concurrent L1 draft/admission and rejection gates, primary stage/deadline/retry limits, read-only pending probes and corruption preservation, switch-off and enabled-L2 comparisons with the frozen public host, durable ingress batching and serial delivery/recovery. `npm run check` includes these automatically. The detailed scope is in [the performance contract](docs/chat-performance.md); final command results belong to the task report, without treating sandbox listener failures as regressions or claiming live model speed/quality from synthetic results.

Fallback coverage includes typed errors and reset windows, persistent breaker backoff and stale-probe protection, HTTP/function-call contracts, timeout/truncation, bounded schema repair, independent review, truthful receipts, replay/uncertain-operation handling, real temporary todo/expense/place stores, both host ingress paths, role-isolated history, explicit Node env-file loading, authenticated WeChat turn IDs and recovery to the primary model. All provider responses and sends are synthetic; no live keys or personal state are read. The public HTTPS primary adapter is tested independently of the omitted private App Server host.

Project code uses Node.js built-in modules and has no external package dependency. Private local vendor packages were omitted, so this repository does not make a redistribution claim about them. The MIT license matches the project publication template; third-party services and any later dependencies retain their own terms.

Source/test text was screened for private identifiers, fixed home paths, credentials, account handles, contact data and cross-project imports. Examples containing identifiable place/itinerary labels were replaced with fictional data. The quota-fallback changes were also screened for real home paths, private runtime/context loaders, known private identity labels and credential-shaped values, with no matches. This screening and synthetic testing do not certify live provider behavior. The private export report and preparation scripts are kept outside this repository.
