# Verification scope

This repository contains source text, fictional tests, public documentation and empty configuration placeholders. It has no runtime snapshot, credentials, vendor archive or original private Git history. The public repository has its own history; a checkout may have an `origin` remote. The pair rework is prepared for a local commit only, without a push or deployment.

`npm test` runs the exported suites in an isolated temporary HOME and temporary-data root, with inherited account/model credentials removed. HTTP, models, map results, notifications and media requests are mocked. Coverage includes classified record persistence/corruption, feature refusals and visibility, exact host account binding, duplicate messages, stable chunk identities and uncertain-operation recovery. Private-host integration assertions were excluded with the private host; their original behavior is not certified here.

`npm run check` checks every shipped JavaScript file's syntax before running tests. `tests/public-pair-console.test.js` adds host-level checks for speaker selection, A-added/B-visible places and visited history, daily-question sealing through a cold reopen, challenge callback results for both roles, savings accumulation and contributor-only undo, personal owner-only permissions, the real console entrypoint and its speaker prompts, and the demo's four scenes and cleanup on both success and failure. Pair store schemas and visibility rules are reused rather than duplicated.

`npm run demo` runs four scenes through the actual local pair console: a shared place is added and marked visited; two daily answers unlock a reveal; two challenge answers produce a consistency result through per-role notices; and two savings entries accumulate to 80 of 200 yuan (40%). Every scene prints both fictional viewpoints. Its temporary runtime is removed in `finally`; the clock and challenge selection are deterministic, with no model or network requests.

The public experience simulates two roles in one local terminal. Role selection is not authentication, and terminal input/scrollback is visible to the operator. Local callback notices are in-memory only; daily reveals and feature records follow their stores' persistence rules. Real two-account WeChat connectivity and relay are not included. The optional network host still accepts only its configured owner and cannot switch roles through message text. These checks do not establish live provider availability, account authorization, actual recipient delivery, model quality, background-service installation or deployment.

Pair rework validation: `npm run check` passes syntax validation and all **1014 tests**, including **9** new pair-console/demo tests, with zero failures or skips. `npm run demo` completes all four fictional scenes locally. This records local verification only, not publication or real-account acceptance.

Project code uses Node.js built-in modules and has no external package dependency. Private local vendor packages were omitted, so this repository does not make a redistribution claim about them. The MIT license matches the project publication template; third-party services and any later dependencies retain their own terms.

Source/test text was screened for private identifiers, fixed home paths, credentials, account handles, contact data and cross-project imports. Examples containing identifiable place/itinerary labels were replaced with fictional data. Scan results support the prepared publication boundary; independent human review is still required before publication. The private export report and preparation scripts are kept outside this repository.
