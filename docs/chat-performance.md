# Ordinary chat performance contract

`ordinary-batch.js` defines a 1,000 ms quiet window capped at 3,500 ms from the first fragment. `public-wechat.js` persists every nonblank text item from each accepted message and its IDs immediately in `state/transport/checkpoint.json`. Multiple text items are joined in original order with newlines. The current batch owns its original `receivedAt`, most recent authenticated context token, concatenated text and `hasAttachment` provenance. A known feature command flushes any preceding ordinary batch and receives a separate job. Only the bound account/owner can enter this queue. The console has no batching timer.

`main.js` calls `pollOnce({waitForIdle:false})`, letting ingress polling continue during the serial model/delivery worker. For tests or custom hosts `pollOnce()` defaults to waiting for buffered work; `idle()` explicitly waits for completion. Neither API should be called concurrently from multiple pollers. A buffered/unstarted job is safe to recover, preserves the original deadline and enters L2; missing media provenance also forces L2. An `executing`/`sending` pending checkpoint continues to stop recovery for inspection. Saved `ready` chunks keep their delivery IDs and resume without re-execution. No expiry cuts off an in-flight result or confirmed chunk bookkeeping.

## Admission and isolation

`chat-lane-policy.js` is a pure no-I/O classifier returning `lane` and `reasonCodes`. Explicitly unknown state fails closed. A narrow greeting whitelist admits L0; a narrow set of stable self-contained text forms admits L1. Anything else stays L2, including media, links, temporal/numeric content, fragments, ambiguous references, instructions to override policy and requested operations. Five additional shape families run **after all existing exclusions and original L0/L1 matches**, with a 16-character limit: `short_acknowledgement`, `short_confirmation`, `repeated_laughter` and `short_personal_state` enter L0; `identity_question` enters L1. State reports must have no request or question suffix. Incomplete references, contextual counterquestions, invitations and advice/action requests stay L2. The hard-gate order is unchanged. Multiple fragments mean at least two nonempty pieces split by `[。！？!?；;…\r\n]+`, the original coordination cues, or at least two comma-separated pieces starting with a recognizable question/request token. Only `，,、` separators are removed for complete original-whitelist matching; original length and numeric/time checks are retained. A comma alone cannot admit unmatched text. This is not a general natural-language intent recognizer and carries no hit-rate guarantee.

`chat-lane-state.js` aggregates boolean probes from the host, not every library in the repository. The single-owner host checks weather/manual state, history readability and optional fallback manual/operation state. The console additionally checks daily-question collection, challenge rounds and same-role place candidates/suggestions/recent lists. The existing personal record routes and savings route require explicit commands and have no conversational pending probe. Any absent/malformed probe result or read failure forces L2. Feature bodies and error messages do not enter lane diagnostics. These probes read without creating, expiring on disk or quarantining feature records; normal feature entrypoints keep their own lifecycle.

An injected weather store must expose a read-only `hasPending(side)` returning a boolean for fast admission and batching. An absent or nonboolean probe disables both for that host. The lane probe never substitutes the existing `pending(side)` accessor, whose normal command lifecycle may persist expiry.

L0 requests strict `{reply:string, needs_tool:boolean}` output, with no extra fields. L1 runs that independent draft alongside two strict `{ordinary:boolean}` requests. Both eligibility results must be true. Those reviewers receive only the original text and bounded same-side history, without a draft or personality profile. The local gate rejects blank/oversized/control-character/structured replies and unsupported Chinese/English execution claims. Any gate failure discards the draft and invokes the original public text model path; no speculative answer is remembered. The public host has no model-controlled executor or repair/planning loop to lend to speculation.

The stock primary `public-model.js` sends no tool catalog, adds `tool_choice:"none"` for staged calls and passes strict JSON schema for fast drafts/review. Unexpected function/tool requests and truncated responses fail. Every HTTP invocation is a fresh stateless request. Primary quota/auth failures do not spend an additional L2 request; typed exhaustion uses the existing quota fallback. An already exhausted request skips lane admission entirely. Providers without schema/permission support need an adapter or `WECHAT_CHAT_LANES=off`.

## Independent fast generation provider

`fastlane-provider.js` reads `FASTLANE_MODEL_ENDPOINT`, `FASTLANE_MODEL_NAME` and `FASTLANE_MODEL_API_KEY` only from env, with no endpoint/model/key defaults. The URL must be a complete HTTPS chat-completion endpoint without URL credentials. All three must be nonempty to select secondary generation; missing configuration selects primary. A configured but invalid endpoint or failed request discards the draft into L2. `WECHAT_FASTLANE_PROVIDER=primary` (case-insensitive) forces primary; absent/`secondary` and other values choose secondary when configured. Selection is evaluated per fast request. See the [README configuration example](../README.md#ordinary-chat-lanes-and-batching). No secondary settings are reused from quota fallback.

The secondary sends `stream:false` and `response_format:{type:"json_object"}` to an OpenAI-compatible endpoint. It registers no tools. Primary and secondary HTTP generation share `buildPublicMessages`: the same current prompt, fixed public persona and bounded last 12 same-side history entries. Neither path loads an external persona/history directory. Custom primary adapters must preserve this no-tool/prompt contract when supplying their own wire format. L1 understanding and independent admission still use the primary adapter, never receiving the draft.

Strict `parseFastAnswer` rejects malformed JSON and additional fields. Any tool/function request (including a tool finish reason), truncated/invalid completion, `needs_tool`, local format failure or unsupported completion claim rejects the draft. Secondary additionally reuses the existing quota-fallback completion-claim checker; primary keeps its existing local gate. Rejection/error/timeout returns the entire request to L2 without a primary replacement draft inside L1. The original L1 control calls remain counted. Only final visible replies enter history.

Secondary makes exactly one attempt with `min(20000ms, originalDeadline-now)`. An AbortController and local Promise race cover fetch and JSON body consumption, including a transport that ignores abort. Expired/cancelled requests never start secondary generation; late results fail the current/deadline check. Timers are cleared on success and failure. This full-call budget has no first-output watchdog or retry; L1 still waits for its parallel primary checks, so it is not a 20-second whole-request SLA.

The existing `public-fallback.js` quota intercept runs before lane admission: exhausted requests bypass secondary and retain independent primary recovery probes and DeepSeek fallback. Primary auth/typed quota failures from L1 checks keep their original terminal handoff; secondary errors, including secondary quota/auth, are draft failures and cannot exhaust primary quota or call its probe/journal. The old six-call/180-second DeepSeek quota fallback and 45-second per-call limit remain separate and unchanged.

## Initial L2 speculative draft

`l2-draft.js` ports the host-only adoption state machine to the public secondary provider. It has no quota, tool, executor or planner APIs. Only an initial L2 path can start it; an L0/L1 rejection going to L2 never creates another draft. `WECHAT_L2_DRAFT=off/false/0`, `WECHAT_FASTLANE_PROVIDER=primary`, lanes off or incomplete `FASTLANE_MODEL_*` configuration disables it per request. Disabled requests add no primary checks. An exhausted fallback intercept never reaches this code; the host rechecks exhaustion before and after waiting for adoption.

Unlike the private task controller, the original public L2 path contains only an ordinary text call. Enabled speculation therefore reuses the existing L1 understanding and independent ordinary-admission prompts/schema as two additional primary checks, in parallel with one secondary draft. Reviewers get the current original text and bounded same-side history, never a draft or upstream products. Both strict `{ordinary:true}` responses attest no tools/execution/retrieval. This public contract maps the private chat/no-actions and approved/no-needs-user checks; it does not implement a task controller or claim identical private wire schemas. A rejection or error immediately invalidates and aborts the draft. Errors in these new adoption-only checks do not change quota state; a rejected attempt invokes the original L2 answer, whose auth/quota behavior is unchanged.

The only adoption point precedes that original answer call. All five conditions are required: both primary checks pass; the original local format/execution gate passes; the existing fallback completion-claim exit check passes; the adapter strictly parses exactly `{reply, needs_tool}` with `needs_tool=false` and rejects tool/function responses; and the generation remains current, within the earliest deadline, with no dispatch/actions/results. Dispatch, exhaustion, cancellation and deadline are rechecked after waiting. Pending, unknown, invalid, recovery/existing-route, context-followup and media exits discard without adopting or adding checks. The public ordinary path has no dispatcher; injected host dispatch guards and the outcome actions/results checks retain the conservative boundary.

Draft inputs use the exact same `buildPublicMessages` as the L0/L1 secondary draft: public persona, last 12 same-side history entries and original current text (with the existing 12,000-character cap). No tools, results, plans or upstream products are appended. The adapter's one attempt uses `min(20000ms, remainingDeadline)`; no retries, deadline extension or extra client. An optional AbortSignal plus Promise race releases cancellation even when fetch/body ignores abort. Without adoption, the original L2 primary history remains unchanged (empty without fallback, bounded same-side history with fallback). No rejected draft enters history.

Timing only appends `draftProvider` (secondary or null), `draftMs` (actual provider time or null) and `draftOutcome`. Existing `provider`, lane and fallback fields keep their meanings. Outcomes: disabled, pending, sent, discarded_needs_pipeline, discarded_check, discarded_gate, discarded_timeout, discarded_error. Sent is adoption, not delivery. The actual secondary model row is buffered until adoption/discard and emitted once with its original attempt/duration/budget; upstream rows already emitted may show pending. No prompts, text, endpoint, model name, key or raw errors enter these records.

## Budgets and retries

`chat-stage-policy.js` preserves these caps:

| Stage | Milliseconds |
| --- | ---: |
| Request understanding / independent admission / semantic review | 40000 |
| Ordinary answer | 60000 |
| Planning from actual results / unknown stage | 120000 |
| Shared primary model and later-dispatch deadline | 150000 |

This public host calls only understanding, admission and ordinary-answer stages; the other policy entries do not create new features. The HTTP timeout is clipped to the remaining shared deadline. Queueing, batching, all speculative attempts, L2 fallback and retry consume the same first-ingress deadline. A custom supplied deadline can shorten it, never extend it. Already invoked actions and delivery finish under their existing lifecycle, so 150 seconds is not a hard wall-clock response SLA. DeepSeek retains its own established six-call/180-second budget and 45-second per-call limit.

Retries belong solely to the host stage runner. Pure understanding/review/ordinary-answer turns may retry once only when explicitly safe, on a fresh request with the remaining budget. An optional safety callback can revoke retry eligibility as dispatch/cancellation occurs. Planning, feature invocation, cleanup and network sending never gain a retry here; auth, quota, budget and unexpected-tool failures never retry. Primary-model fast drafts allow one retry **only** when `timeoutReason` is exactly `first_output_watchdog`; ordinary stage timeouts, network errors, malformed/schema output and gate rejections do not trigger a draft retry. The existing safety check and shared deadline still apply; a second watchdog failure discards the draft into the original L2 fallback. This retry exception does not bypass either L1 reviewer or any local gate. The HTTP adapter never retries independently.

## First output signal

The stock `public-model.js` sends a non-streaming chat-completion request (no `stream: true`) and awaits `response.json()`. It consumes neither SSE increments nor response-body chunks as model activity. HTTP headers are not model output, and a complete JSON response cannot reveal when generation first began. Therefore the stock adapter has **no 15-second first-output watchdog**. It retains the full stage timeout clipped by the shared deadline; a timeout during fetch or JSON body consumption is `stage_budget`, never `first_output_watchdog`. Its `firstOutputMs` remains null, including on success.

The stage runner passes `firstOutputTimeoutMs: 15000` for request understanding, independent ordinary admission and ordinary answers (including L0/L1 drafts). This is a policy hint for a custom adapter with a genuine activity signal, not a shorter HTTP timeout. Semantic execution review, result planning and unknown stages receive no first-output hint. This primary hint remains an injectable adapter contract; the secondary non-streaming provider uses its separate full-call 20-second budget and never consumes this hint.

A custom `model(text, options)` adapter that implements the hint must start it when the model turn starts, abort the request if no genuine nonempty model output occurs within 15 seconds, disarm it after the first output, and retain the full stage/deadline limit thereafter. Headers, lifecycle/usage metadata and empty increments cannot disarm it. A watchdog abort must reject with typed `timeoutReason: "first_output_watchdog"` and a timeout-class error (the public host uses `TRANSIENT`), while auth/quota/budget/unexpected-tool failures retain their own types. The adapter must not retry internally. It may call `options.onTiming({timeoutReason, firstOutputMs})`; `firstOutputMs` measures model-turn start to first actual output. Only known timeout reasons and nonnegative finite milliseconds enter host timing; extra fields and raw provider messages are omitted. These callback and retry paths are covered by synthetic adapters only, not a live streaming integration.

## Switch, history and timing

`WECHAT_CHAT_LANES` is read on each request; absent/`on` enables lanes, and `off`/`false`/`0` disables classification, probes and speculative calls. The baseline primary text path, feature parsing, quota fallback and delivery are retained. Batching, stage policy and diagnostic fields remain active with lanes off. The frozen `tests/public-assistant-baseline.cjs` is the pre-change public host with import paths adjusted for the test directory; differential tests compare successful primary and feature routing rather than claiming the newly introduced retry/deadline policy existed in that host.

Visible replies use `state/chat/threads.json`, keyed by account/sender/role, at most 24 entries per thread and a 30-day inactive read expiry. Fast drafts and admission may read the last 12 entries; fallback-enabled primary/DeepSeek retain the same bounded history. Without fallback, L2/off still sends only current text to the primary model. History read failures cannot grant a fast lane; new appends preserve malformed JSON rather than replacing it. No cross-role history or external context loader exists. The console retains its existing visibility rules for pair answers/notices; the local terminal remains visible to its operator.

`main.js` writes timing JSON to stderr with ISO timestamps and existing `model timing` / `chat timing` prefixes. Records include `provider`, stages, attempts, safe retry/fallback reasons, lane/effective lane and durations; model records additionally include `timeoutReason` (null, `stage_budget`, `first_output_watchdog` or secondary `fastlane_budget`), `firstOutputWatchdog` (true only for that watchdog abort) and `firstOutputMs` (null when unobservable/no output). Per-model `provider` is the actual caller (`primary`/`secondary`); request-level `provider` identifies the selected draft generator, retained after L2 fallback. An already exhausted bypass reports `deepseek`. Safe draft fallback reasons have `primary_`/`secondary_` prefixes (for example `secondary_timeout`, `secondary_invalid_output`, `secondary_unexpected_tool`); shared `check_fail` and `stale_or_budget` retain their names. Count watchdog failures from per-attempt `model timing` rows; request-level `chat timing` still describes final routing and total attempts; WeChat adds batch/queue/processing/delivery times and confirmed server acceptance. Opaque random trace IDs correlate records without account/sender IDs. No text, prompts, credentials, provider bodies or raw exceptions are logged. Model/processing timing is recorded when that phase finishes; later fallback/rejection is reflected in subsequent/final records, not rewritten into earlier rows. Direct console replies have no network-delivery claim.

## Validation scope

`tests/chat-lanes-cases.json` has 71 fictional cases: L0 15, L1 13, L2 43, including pending traps, mixed requests, fragments, media, unsupported requests, injection attempts and unknown facts/state. Each case states lane, allowed/forbidden tool bounds and a no-execution assertion. `tests/chat-lane-shapes.test.js` adds 10 generic paraphrases across the five new families, each with 15 near-miss traps (150 total), plus 11 incomplete/contextual/request variants kept in L2. These are paraphrase fixtures from the source evaluation, not production message exports. The original 52-case records are unchanged; 19 source synthetic comma/fragment cases are appended. Ten change lane versus round four and six change only reason. All 71 cases force L2 under pending/unknown/attachment/batch gates (284 checks). `tests/l2-draft.test.js` covers all adoption conditions, original-answer rejection, cancellation/abort, switches, same-prompt byte equality and both hosts with breaker isolation. `tests/fastlane-provider.test.js` compares actual primary/secondary wire prompts and exercises both hosts, runtime selection, missing config, concurrent L1 review, strict parsing/tool rejection, complete-call deadlines/abort, L2 fallback without replacement, role history and quota isolation. Stage/host/HTTP tests cover watchdog-only retries, cancellation, shared deadlines, retry limits, timing fields and the stock adapter retaining its non-streaming stage timeout. The classifier/harness never executes tools; any L2 tool allowance describes the existing fallback adapter's upper bound, not a command to execute. Host/store/transport tests separately exercise actual local writes, role isolation, read-only failure preservation, deadlines, concurrent ingress, uncertain-operation holds and baseline behavior. All model/provider/send responses are synthetic. These checks do not prove real-model quality, latency improvement, production coverage, WeChat connectivity or recipient delivery.
